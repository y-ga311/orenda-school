## 1. 概要

### 1.1 目的

Orenda School 教員ポータルは、看護・医療系専門学校における教員が、学生の学習状況の確認・試験成績の管理・教材（問題・クエスト）の編集・各種マスタ登録を行うための Web アプリケーションである。

本ドキュメントは、UI デザイン（Pencil `.pen` ファイル）をもとに整理した要件定義であり、実装フェーズの共通認識として利用する。

### 1.2 スコープ

| 対象 | 内容 |
|------|------|
| 対象アプリ | 教員向け Web ポータル（Teacher Portal） |
| 対象ユーザー | **教員のみ** |
| 関連アプリ（対象外） | 学生向けアプリ **Orenda**（`Dropbox/Orenda`）。スマホ PWA 向け。詳細要件は同アプリ側の `docs/requirements/` を参照 |
| 成果物の位置づけ | 現フェーズは UI モックアップ（本リポジトリ）。実装は段階リリース予定 |

### 1.3 プロダクト構成

```
Dropbox/
├── Orenda/              … 学生向けアプリ（スマホ PWA）
└── Orenda-School/       … 教員ポータル（本書・PC Web）← 本要件
         │
         └── 同一 Supabase プロジェクトでデータ共有
```

## 2. 対象ユーザー

| ユーザー種別 | 説明 | 主な操作 |
|-------------|------|---------|
| 教員 | クラス担当・科目担当の教員 | 成績確認、教材編集、学生情報登録、保護者連絡 |

**確定事項**

- 教員のみが利用する（学生・保護者・事務職専用アカウントは設けない）
- 教員ロールの細分化（管理者／閲覧のみ等）は **現時点では設けない**（全教員が同一権限を想定。必要になれば将来追加）

- オフライン利用は対象外

## 4. システム構成

### 4.1 アーキテクチャ

```
[教員 PC ブラウザ]
        │
        ▼
[教員ポータル Web アプリ]  ← Next.js（本リポジトリで実装予定）
        │
        ▼
[Supabase]
  ├── Auth          … 教員アカウント管理
  ├── PostgreSQL    … 学生・成績・教材・保護者連絡等（SQL）
  ├── RLS           … 行レベルセキュリティ（教員のみアクセス可）
  └── Storage       … 必要に応じて画像等
        ▲
        │ 同一 DB を参照
        │
[学生アプリ Orenda]  ← Next.js PWA（../Orenda）
```

**確定事項**

| 項目 | 方針 |
|------|------|
| 認証 | **Supabase Auth** で教員アカウントを管理 |
| データベース | **Supabase PostgreSQL（SQL）** |
| 外部連携 | 別 API は使わず、**Supabase 上の同一データ**を教員ポータル・学生アプリ双方から参照・更新 |
| 既存システム連携 | **なし**（学籍管理・LMS 等との連携は現時点で考えていない） |
| リリース | **段階リリース（MVP 分割）** — §4.3 参照 |

### 4.2 認証方針（教員 vs 学生）

| アプリ | 認証方式 | 備考 |
|--------|---------|------|
| 学生アプリ（Orenda） | `students` テーブルの `gakusei_id` / `gakusei_password` | 既存実装済み |
| 教員ポータル（本アプリ） | **Supabase Auth**（メール + パスワード等） | 教員用 `teachers` または `profiles` テーブルと Auth UID を紐付け |

- 学生認証と教員認証は **別方式** とし、RLS でアクセス可能なデータを分離する
- 教員のみが書き込み可能なテーブル（成績登録・問題承認等）と、学生が読み取るテーブルを RLS で制御

### 4.3 MVP 段階リリース計画（案）

全 16 画面（教員向け）を一括ではなく、以下の順で段階リリースする。

| フェーズ | 対象画面 | 目的 |
|--------|---------|------|
| **Phase 1** | 教員ログイン、定期試験、模擬試験、卒業試験 | 認証基盤 + 最も利用頻度の高い成績確認 |
| **Phase 2** | 学習時間（個人別）、学習時間ランキング、科目別推移 | 学習分析・可視化（学生アプリの学習ログを参照） |
| **Phase 3** | Orenda 編集、教員クエスト、学生投稿問題 | 教材 CRUD・承認フロー（学生アプリへ即反映） |
| **Phase 4** | メダル設定、国家試験日程、試験問題数設定 | マスタ・設定系 |
| **Phase 5** | 新規学生登録、試験結果登録、学生基本情報 | データ登録・更新 |
| **Phase 6** | つながるポータル保護者連絡 | 保護者連絡（Supabase 同一データ） |

※ フェーズ順・範囲は開発着手時に調整可能

## 5. 技術スタック（推奨）

学生アプリ **Orenda** と同一 Supabase プロジェクトを共有するため、**Orenda と揃えた構成**を推奨する。

### 5.1 推奨スタック

| レイヤ | 技術 | 選定理由 |
|--------|------|---------|
| フロントエンド | **Next.js 16 + React 19 + TypeScript** | Orenda と同一。App Router、API Routes、型安全 |
| UI | **Tailwind CSS + shadcn/ui** | PC 向け管理画面に適したテーブル・フォーム・ダイアログ。Orenda 要件メモでも Tailwind を候補に記載 |
| グラフ | **Recharts** | 学習時間ランキング・科目別推移の棒グラフ／積み上げグラフに適合 |
| 認証 | **Supabase Auth** + `@supabase/ssr` | 教員セッション管理、Server/Client 両対応 |
| データアクセス | **Supabase JS Client** + **SQL（PostgreSQL）** | 直接クエリ、RPC、RLS。Orenda 既存パターンを踏襲 |
| バリデーション | **Zod** | フォーム・API 入力の型付きバリデーション |
| ホスティング | **Vercel** | Orenda と同様。Preview 環境で段階リリースに有利 |
| マイグレーション | **Supabase CLI**（`supabase/migrations/`） | SQL を Git 管理。Orenda の `docs/sql/` と統合または共通化 |

### 5.2 採用しないもの（現時点）

| 技術 | 理由 |
|------|------|
| 別途バックエンド（Express / FastAPI 等） | Supabase + Next.js API Routes で足りる。運用コスト削減 |
| 別 DB（Firebase 等） | Supabase SQL で統一済み |
| モノレポ強制 | 2 アプリは別リポジトリのままでよい。Supabase プロジェクトと型定義のみ共有可能 |

### 5.3 ディレクトリ構成（実装時の目安）

```
Orenda-School/
├── app/                    # Next.js App Router
│   ├── (auth)/login/
│   ├── (dashboard)/        # サイドバー付きレイアウト
│   │   ├── exams/
│   │   ├── study-time/
│   │   └── orenda-edit/
│   └── api/                # 教員専用 API（必要時）
├── components/
├── lib/
│   └── supabase/           # client / server / middleware
├── supabase/
│   └── migrations/         # SQL マイグレーション
└── pen-files/              # デザイン（現状）
```

### 5.4 学生アプリとのコード共有

| 共有可能 | 内容 |
|---------|------|
| ○ | Supabase 型定義（`database.types.ts`）、定数、日付ユーティリティ |
| ○ | SQL マイグレーション（同一 Supabase プロジェクト） |
| × | UI コンポーネント（端末・画面サイズが異なる） |
| × | 認証フロー（教員 Auth vs 学生 ID/パスワード） |

## 7. 共通 UI 要件

### 7.1 レイアウト

- **左サイドバー（固定）**：アプリロゴ「Orenda School」、ナビゲーションメニュー
- **メインコンテンツエリア**：ページタイトル、フィルター、データ表示／フォーム
- **ヘッダー／フッター**：画面により固定ヘッダー・固定フッター（例：教員クエスト編集画面）

### 7.2 サイドバーナビゲーション

```
確認画面
  ├── 学習時間（個人別）
  ├── 学習時間ランキング
  ├── 定期試験
  ├── 模擬試験
  ├── 卒業試験
  └── 科目別推移

編集・登録
  ├── 学生基本情報
  ├── 試験問題数設定
  ├── 新規学生登録
  ├── 試験結果登録
  ├── Orenda 編集
  └── つながるポータル保護者連絡
```

- 現在表示中の画面はサイドバーでハイライト表示
- クラス・期生選択（例：「23 期生昼間部」）は画面上部またはサイドバー付近に配置
- 未リリースフェーズのメニュー項目は非表示または「準備中」表示

### 7.3 共通コンポーネント

| コンポーネント | 説明 |
|--------------|------|
| 期生・クラスセレクタ | 表示対象クラスの切り替え |
| 学生一覧テーブル | ソート・フィルター可能な一覧 |
| タブ UI | 試験種別・科目・問題番号などの切り替え |
| 日付ピッカー | 公開日・終了日・試験日等 |
| トースト／モーダル | 保存完了・エラー通知 |

## 8. 機能要件

### 8.1 教員ログイン（`teacher-login`）

| ID | 要件 |
|----|------|
| AUTH-01 | Supabase Auth で教員アカウント（メール + パスワード等）によりログインできる |
| AUTH-02 | ログイン成功後、デフォルト画面（定期試験等）へ遷移する |
| AUTH-03 | 認証失敗時はエラーメッセージを表示する |
| AUTH-04 | 教員アカウントは Supabase 側で事前登録（または招待）する |
| AUTH-05 | セッションは Supabase Auth の JWT で管理し、未認証時はログイン画面へリダイレクト |

### 8.2 定期試験・模擬試験・卒業試験（確認画面）

3 画面は同一レイアウトパターンで、試験種別のみ異なる。

| EXAM-03 | 試験種別（定期／模擬／卒業）で専用画面に分離 |
| EXAM-04 | 個別学生の詳細成績を確認できる（ドリルダウンまたは別パネル） |
